## 1. 🔥 CRISIS DEL SCROLL (COLAPSO REAL)

### ESCENARIO:

Usuario:

* Hace scroll brutal (flick iOS)
* 10 fragmentos en cola
* 10 fetch simultáneos
* IntersectionObserver disparando en cascada

---

## 💣 LO QUE PASA REALMENTE

### 🔴 1. Cola de Promesas → RAM explosion

```js
fetch(chunk1)
fetch(chunk2)
fetch(chunk3)
...
```

👉 Safari NO cancela → acumula
👉 RAM sube → GC entra → freeze → crash

---

### 🔴 2. IntersectionObserver flood

* Dispara múltiples callbacks simultáneos
* Cada uno intenta cargar fragmentos

👉 Resultado:
**duplicación de cargas + jitter**

---

### 🔴 3. Paint storm

* Insertas múltiples fragments
* Layout recalculation masivo

👉 GPU + CPU = 🔥

---

## 🧠 SOLUCIÓN (BRUTAL, NO BONITA)

---

### 🧱 LIMITADOR DE CARGA (IMPRESCINDIBLE)

```js
let loading = false;

async function safeLoad(id) {
  if (loading) return;
  loading = true;

  await loadChapter(id);

  loading = false;
}
```

---

### 🧨 CANCELACIÓN DE FETCH (CLAVE)

```js
let controller;

async function loadChapter(id) {
  if (controller) controller.abort();

  controller = new AbortController();

  const res = await fetch(`/book/${id}.html`, {
    signal: controller.signal
  });

  const html = await res.text();
}
```

---

### 🧠 THROTTLE DE SCROLL (NO OPCIONAL)

```js
let last = 0;

window.addEventListener('scroll', () => {
```

👉 Resultado:

* cache corrupta
* recursos faltantes
* comportamiento errático

---

## 🔴 LÍMITE EMPÍRICO

* ~50–70 requests simultáneos → peligro
* > 100 → **OOM probable**

---

## 🧠 SOLUCIÓN

👉 Caching progresivo

```js
async function cacheChunk(urls) {
  const cache = await caches.open('book');

  for (const url of urls) {
    await cache.add(url);
  }
}
```

---

## 2. 🧨 INDEXEDDB VS CACHE STORAGE

---

## ⚔️ CACHE STORAGE

### PROS:

* simple
* HTTP-like

### CONS:

* opaco
* sin control granular
* mala gestión de blobs grandes

---

## ⚔️ INDEXEDDB

### PROS:

* control total
* chunking manual
* persistencia fiable

### CONS:

* complejo
* asincrónico pesado

---

## 💣 PROBLEMA CRÍTICO

WebP + HTML:

👉 Cache:

* guarda como Response
* ocupa RAM indirecta

👉 IndexedDB:

* puedes guardar como string / blob fragmentado

---

---

---
