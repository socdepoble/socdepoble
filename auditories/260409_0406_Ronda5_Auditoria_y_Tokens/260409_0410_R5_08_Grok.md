### 1. AUDITORÍA EXTREMA – Las grietas invisibles que quedan

**Fisura A: IndexedDB Eviction Policy (Jetsam Killer en Safari 14.1)**  
Safari iOS 14.8 aplica **jetsam** agresivo: cuando la memoria física baja de ~300 MB libres, el sistema **mata silenciosamente** las transacciones IDB más grandes sin disparar error visible. El `IDBTransaction` se aborta, los blobs de tomos se corrompen parcialmente y al recargar el manifest.json queda inconsistente.  
Consecuencia real: después de 8-10 sesiones largas, el usuario pierde los últimos 4 tomos cacheados. La *iaia* ve “el libro se ha roto otra vez”.

**Solución quirúrgica (código obligatorio):**  
Implementar **quota guard + atomic write + fallback automático**:

```js
// db.js – Gestor de IndexedDB blindado
const DB_NAME = 'socdepoble-v2';
const STORE_NAME = 'tomos';

async function openDB() {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open(DB_NAME, 2);
    req.onupgradeneeded = e => {
      const db = e.target.result;
      if (!db.objectStoreNames.contains(STORE_NAME)) {
        db.createObjectStore(STORE_NAME, { keyPath: 'id' });
      }
    };
    req.onsuccess = e => resolve(e.target.result);
    req.onerror = e => reject(e.target.error);
  });
}

async function saveTomoSafe(id, htmlBlob, realHeight) {
  const db = await openDB();
  const tx = db.transaction(STORE_NAME, 'readwrite');
  const store = tx.objectStore(STORE_NAME);
  
  // Quota guard previo (Safari 14.1 no da navigator.storage.estimate fiable → medición manual)
  const currentSize = await estimateDBSize(); // función abajo
  if (currentSize > 38 * 1024 * 1024) { // 38 MB umbral seguro
    await purgeOldestTomos(2); // borra los 2 más antiguos
  }
  
  const entry = { id, html: htmlBlob, height: realHeight, timestamp: Date.now() };
  return new Promise((resolve, reject) => {
    const req = store.put(entry);
    req.onsuccess = () => resolve(true);
    req.onerror = () => {
      console.error('💥 IDB eviction detectada – fallback a Cache API');
      fallbackToCache(id, htmlBlob); // función definida abajo
      reject(req.error);
    };
  });
}

// Estimación manual de tamaño (la única fiable en Safari 14)
async function estimateDBSize() {
  const db = await openDB();
  const tx = db.transaction(STORE_NAME, 'readonly');
  const store = tx.objectStore(STORE_NAME);
  return new Promise(resolve => {
    const req = store.getAll();
    req.onsuccess = e => {
      let size = 0;
      e.target.result.forEach(entry => {
        size += (entry.html?.length || 0) + (entry.height ? 8 : 0);
      });
      resolve(size);
    };
  });
}
```

**Fisura B: PWA Cache Corruption (Service Worker stale + update fallido)**  
En offline total, si el SW intenta `skipWaiting()` o hay un update fallido por 3G intermitente, el cache queda en estado “stale-while-revalidate” corrupto. Al recargar, Safari sirve tomos viejos con manifest inconsistente → alturas erróneas → scroll jumps de 1200 px.

**Solución:** Cache versioning agresivo + self-healing en activate:

```js
// sw.js – Versión blindada
const CACHE_VERSION = 'socdepoble-v20260409';
self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(keys => 
      Promise.all(
        keys.map(key => {
          if (key !== CACHE_VERSION) return caches.delete(key);
        })
      )
    ).then(() => self.clients.claim())
  );
});

// En fetch para tomos: siempre validar versión del manifest
if (request.url.includes('/contenido/tomo-')) {
  event.respondWith(
    caches.match(request).then(cached => {
      if (cached) return cached;
      return fetch(request).then(response => {
        const clone = response.clone();
        caches.open(CACHE_VERSION).then(cache => cache.put(request, clone));
        return response;
      });
    })
  );
}
```

**Fisura C: Estrangulamiento energético + P2P offline (futuro multi-dispositivo)**  
Aunque ahora es single-device, el proyecto Sóc de Poble aspira a sincronización local entre masías (WebRTC o WebTransport). Cada observer + rAF + IDB write consume ~8-12 % batería/hora en idle. Con 20 tomos y hljs diferido, el A10 se calienta y entra thermal throttle en 45 minutos.

**Solución:** Battery-aware + suspend mode:

// energy-guard.js
let batteryLevel = 100;
navigator.getBattery?.().then(battery => {

  battery.addEventListener('levelchange', () => {
    batteryLevel = battery.level * 100;
    if (batteryLevel < 25) enterLowPowerMode();
  });
});

**Fisura D: Manifest drift por altura variable + GC spikes**  
El rebuildCumulative() se llama en cada ajuste de altura. En iPad con 40 tomos → 40 llamadas seguidas → GC spike de 120 ms → frame drop.

**Solución final:** Debounce + batch update:

```js
let rebuildTimeout = null;
function scheduleRebuild() {
  if (rebuildTimeout) clearTimeout(rebuildTimeout);
  rebuildTimeout = setTimeout(() => {
    rebuildCumulative();
    updatePool(scroller.scrollTop);
  }, 180); // 180 ms batch
}
```
