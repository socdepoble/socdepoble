### **🔴 VECTOR 1: Límites Oscuros de IndexedDB en Safari (Eviction Policies)**
**Problema:**
- Safari 14.1 tiene un límite **real** de **500MB** para IndexedDB, pero en dispositivos con **2GB RAM total**, el sistema operativo puede eliminar bases de datos arbitrariamente si hay presión de memoria (ej: 3 apps abierta + PWA).
- **Eviction policies** de Safari son **opacas**: no hay forma de predecir cuándo borrará una base de datos. En la España Vaciada, los dispositivos suelen tener solo **200MB libres** tras arrancar.

**Solución:**
1. **Dividir la base de datos** en múltiples (<=200MB cada una).
2. **Health Check periódico**: Verificar el espacio libre antes de cada escritura.
3. **Compaction automática**: Eliminar registros antiguos o duplicados cada 10 minutos.
4. **Transacciones atómicas**: Usar `IDBTransaction` con `readwrite` para evitar corrupción.

**Código (Corregido y Minimizado):**
```javascript
// Health Check + Compaction cada 10 minutos
async function checkIndexedDBSpace() {
    return new Promise((resolve) => {
        const dbRequest = indexedDB.open('socdepoble-health', 1);
        dbRequest.onsuccess = () => {
            const db = dbRequest.result;
            const tx = db.transaction(['health'], 'readonly');
            tx.objectStore('health').get('space').onsuccess = (e) => {
                resolve(e.target.result?.freeSpace || 0);
            };
        };
        dbRequest.onerror = () => resolve(0);
    });
}

setInterval(async () => {
    const freeSpace = await checkIndexedDBSpace();
    if (freeSpace < 50 * 1024 * 1024) { // 50MB libres
        const db = await openDB('socdepoble-main', 1);
        await db.delete('fragments', null, { allKeys: true });
        console.warn('[INDEXEDDB] Compactado por espacio bajo.');
    }
}, 600000); // 10 minutos
```

### **🔴 VECTOR 2: Corrupción de Caché PWA (Torch Mode + Jetsam)**
**Problema:**
- La **Cache API** en Safari 14.1 puede corromperse si:
  - Hay un **cierre forzoso** (Jetsam).
  - El dispositivo entra en **torch mode** (baja batería + alta temperatura).
- No hay forma de verificar la integridad de los recursos cacheados. Un solo bit corrupto inutiliza la PWA.

**Solución:**
1. **Checksums por recurso**: SHA-256 para cada archivo cacheado.
2. **Validación en Service Worker**: Comparar checksums al servir recursos.
3. **Reconstrucción automática**: Si hay corrupción, volver a descargar el recurso.

**Código (Service Worker + Checksums):**
```javascript
// Service Worker: Validación de caché con checksums
self.addEventListener('fetch', (event) => {
    event.respondWith(
        caches.open('offline-v1').then(async (cache) => {
            const response = await cache.match(event.request);
            if (response) {
                const storedChecksum = await response.headers.get('x-checksum');
                const actualChecksum = await calculateChecksum(await response.clone().text());
                if (storedChecksum === actualChecksum) {
                    return response;
                } else {
                    console.error('[CACHE] Corrupción detectada, reconstruyendo...');
                    await cache.delete(event.request);
                    return fetch(event.request);
                }
            }
            return fetch(event.request);
        })
    );
});

// Función de checksum (simplificada para Safari 14.1)
```

### **🔴 VECTOR 3: Sincronización P2P Offline (Sin Red, Sin Esperanza)**
**Problema:**
- En zonas rurales sin conexión, los dispositivos deben sincronizarse **P2P** (Bluetooth/Wi-Fi Direct).
- **Bluetooth** en iOS 14.8 tiene un límite de **10 metros** y **ancho de banda bajo**.
- **Wi-Fi Direct** es inestable en dispositivos antiguos.
- No hay un protocolo P2P robusto para iOS 14.8.

**Solución:**
1. **WebRTC + CRDT-like**:
   - Usar **WebRTC DataChannel** para P2P directo.
   - Implementar un protocolo basado en **hashes** (como CRDTs) que solo transfiera cambios.
   - **Semáforos**: Evitar colisiones con un sistema de prioridades (fragmentos recientes primero).

2. **Almacenamiento temporal**:
   - Usar **IndexedDB** como cola de sincronización.
   - Priorizar fragmentos con timestamp más reciente.

**Código (Protocolo P2P Simplificado):**
```javascript
class PeerSync {
    constructor() {
        this.peers = new Map();
        this.localFragments = new Map(); // {id: {hash, timestamp, data}}
    }

    async syncWithPeer(peerId) {
        const data = await this.getFragmentsHashes();
        const peer = this.peers.get(peerId);
        await peer.send(data);
        peer.on('message', (msg) => this.mergeRemoteFragments(msg));
    }

    mergeRemoteFragments(remoteHashes) {
        remoteHashes.forEach(({id, hash, timestamp}) => {
            if (!this.localFragments.has(id) || timestamp > this.localFragments.get(id).timestamp) {
                this.requestFragment(id, hash);
            }
        });
    }

    async requestFragment(id, hash) {
        // Implementar con WebRTC DataChannel
        const peer = this.peers.values().next().value;
        await peer.send({ type: 'REQUEST_FRAGMENT', id, hash });
    }
}
```

### **🔴 VECTOR 4: Eficiencia Energética Límite (Batería de 32.4 Wh)**
**Problema:**
- El iPad A10 tiene una batería de **32.4 Wh**.
- **Virtual Scrolling + Web Workers** consumen energía extra.
- Safari 14.1 no optimiza el uso de CPU/GPU para PWA.

**Solución:**
1. **Modo Ahorro**:
   - Reducir FPS a **15** cuando la batería esté <30%.
   - Desactivar **Web Workers** y usar `setTimeout` en su lugar.
   - Reducir el **pool de nodos** a **2** (no 3).
2. **Monitoreo de batería**:
   - Usar `navigator.getBattery()` para ajustar el modo ahorro.

**Código (Modo Ahorro):**
```javascript
async function setupPowerSaveMode() {
    if ('getBattery' in navigator) {
        const battery = await navigator.getBattery();
        battery.addEventListener('levelchange', () => {
            if (battery.level < 0.3) {
                console.warn('[BATERÍA] Modo ahorro activado.');
                // Reducir FPS a 15
                window.requestAnimationFrame = (cb) => setTimeout(cb, 66);
                // Desactivar Web Workers
                window.Worker = null;
                // Reducir pool de nodos a 2
                virtualScroller.poolSize = 2;
            }
        });
    }
}
```
