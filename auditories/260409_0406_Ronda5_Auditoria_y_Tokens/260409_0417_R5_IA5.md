### 1. Vectores críticos y fallos explotables (Red Team)
**1.1 IndexedDB: límites oscuros y corrupción**
- **Problema**: Safari/WebKit aplica cuotas por origen no documentadas, y puede purgar datos sin aviso; además implementaciones antiguas pueden corromper transacciones si hay cierres abruptos o escrituras concurrentes grandes.
- **Síntomas**: `QuotaExceededError` silencioso, datos parcialmente escritos, transacciones bloqueadas, pérdida de blobs grandes.
- **Explotos**: escritura masiva concurrente (install prefetch) → bloqueo del event loop → jetsam kill; manipulación de keys para forzar GC y purga.

**1.2 Cache Storage: OOM y fallos silenciosos**
- **Problema**: `caches.addAll()` puede intentar mantener respuestas en memoria antes de persistir; en Safari con memoria baja provoca OOM o fallos en `install` sin rollback.
- **Síntomas**: SW `install` falla parcialmente; PWA arranca sin fragments; recursos no disponibles offline.
- **Explotos**: forzar install con lista grande de recursos; inyectar respuestas corruptas para romper la cache.

**1.3 PWA manifest / SW tampering y actualización parcial**
- **Problema**: manifest/fragmentos no firmados permiten MITM o corrupción local; actualización parcial puede dejar manifest y fragments fuera de sincronía.
- **Síntomas**: mismatched manifest → heights incorrectos → layout thrash; contenido desactualizado o malicioso servido offline.
- **Explotos**: manipular manifest para forzar reflows o inyectar scripts en fragments.

**1.4 P2P offline sync: partición y conflicto**
- **Problema**: sincronización P2P (WebRTC/DataChannel) sin control de versiones y sin anti-entropy puede producir divergencia, duplicados y crecimiento indefinido de storage.
- **Síntomas**: múltiples versiones de un mismo fragmento; aumento de blobs; conflictos no resueltos que consumen quota.
- **Explotos**: enviar versiones conflictivas repetidas para forzar almacenamiento y quota exhaustion.

**1.5 Eficiencia energética y thermal death**
- **Problema**: ráfagas de parse + decode + highlight + writes simultáneos generan long tasks y GC que elevan temperatura y activan jetsam.
- **Síntomas**: FPS drop, long tasks, GC spikes, procesos matados.
- **Explotos**: swipe extremo combinado con prefetch agresivo y highlight en main thread.

**1.6 Integridad y autenticidad**
- **Problema**: ausencia de firma de contenido permite inyección de contenido malicioso o corrupto en offline.
- **Síntomas**: contenido modificado, imágenes/HTML corruptos, XSS si no se sanitiza.
- **Explotos**: inyección de payloads en fragments que se rehidratan sin validación.

### 2. Principios de endurecimiento (decisiones arquitectónicas)
1. **Zero-trust de contenido**: todo fragmento y asset debe llevar **firma criptográfica** (Ed25519) y checksum (SHA-256) en el `manifest.json`. Validar antes de rehidratar o almacenar.  
2. **Hybrid store con streaming y WAL**: Cache Storage para shell y JS; **IndexedDB** para fragments e imágenes grandes, escritos por **chunked streaming** con **Write-Ahead Log (WAL)** para atomicidad y recuperación.  
3. **Budgeted background work**: todas las operaciones intensivas (parse, highlight, writes) se someten a un *budget engine* que usa `navigator.deviceMemory`, `hardwareConcurrency`, `battery` y señales de perf (FPS, long tasks).  
4. **Eviction determinista**: LRU con cuota adaptativa y compaction incremental; no confiar en purga del navegador. Implementar política local y meta‑replicación.  
5. **Anti-entropy y CRDT para P2P**: usar CRDTs (p. ej. RGA o LWW-element-set) para contenido colaborativo y anti-entropy para sincronización eventual con bounded growth.  
6. **Fail-safe degrade**: si jetsam/heap/thermal detectado, pasar a modo crítico: solo nodo central, no prefetch, highlights off, writes en cola.  
7. **Integrity-first SW**: service worker valida firmas, sirve desde IDB si cache corrupta, y mantiene versión semántica del manifest.

### 3. Código: almacenamiento chunked, WAL, LRU y verificación de firma
**3.1 Utilidades criptográficas (SubtleCrypto)**

```js
// verifySignature.js
export async function verifySignature(publicKeyJwk, messageArrayBuffer, signatureArrayBuffer) {
  const key = await crypto.subtle.importKey(
    'jwk', publicKeyJwk, {name:'NODE-ED25519', namedCurve:'Ed25519'}, false, ['verify']
  ).catch(()=>null);
  if(!key) throw new Error('No crypto key');
  return crypto.subtle.verify({name:'NODE-ED25519'}, key, signatureArrayBuffer, messageArrayBuffer);
}
```

> Nota: WebCrypto en Safari puede requerir adaptadores; si Ed25519 no disponible, usar ECDSA P-256 con JWS.

// idb-store.js (simplified)
const DB_NAME = 'socdepoble-store-v1';
const STORE_BLOBS = 'blobs';
const STORE_WAL = 'wal';
const STORE_META = 'meta';

function openDB(){
  return new Promise((res, rej) => {
    const r = indexedDB.open(DB_NAME, 1);
    r.onupgradeneeded = e => {
      const db = e.target.result;
      db.createObjectStore(STORE_BLOBS, {keyPath:'key'});
      db.createObjectStore(STORE_WAL, {autoIncrement:true});
      db.createObjectStore(STORE_META, {keyPath:'key'});
    };
    r.onsuccess = () => res(r.result);
    r.onerror = () => rej(r.error);
  });
}

**3.3 Chunked write with WAL and checksum**

```js
// store-chunked.js
async function storeStreamWithWAL(key, stream, expectedSha256Hex, publicKeyJwk, signature) {
  const db = await openDB();
  const tx = db.transaction([STORE_WAL, STORE_BLOBS, STORE_META], 'readwrite');
  const walStore = tx.objectStore(STORE_WAL);
  const blobs = tx.objectStore(STORE_BLOBS);
  const meta = tx.objectStore(STORE_META);

  // 1) write WAL entry
  const walId = await new Promise((res,rej)=> {
    const req = walStore.add({key, status:'writing', ts:Date.now()});
    req.onsuccess = ()=>res(req.result);
    req.onerror = ()=>rej(req.error);
  });

  // 2) stream read and write chunks
  const reader = stream.getReader();
  const chunks = [];
  const sha = await crypto.subtle.digest('SHA-256', new Uint8Array()); // placeholder
  // We'll accumulate in small blobs and flush periodically
  let buffer = [];
  let flushCount = 0;
  while(true){
    const {done, value} = await reader.read();
    if(done) break;
    buffer.push(value);
    if(buffer.length >= 8){ // flush threshold
      const blob = new Blob(buffer);
      await new Promise((res,rej)=>{
        const putReq = blobs.put({key: `${key}.part.${flushCount}`, blob, ts:Date.now()});
        putReq.onsuccess = res; putReq.onerror = rej;
      });
      buffer = []; flushCount++;
      // yield to event loop
      await new Promise(r => setTimeout(r, 0));
    }
  }
  if(buffer.length){
    const blob = new Blob(buffer);
    await new Promise((res,rej)=>{
      const putReq = blobs.put({key: `${key}.part.${flushCount}`, blob, ts:Date.now()});
      putReq.onsuccess = res; putReq.onerror = rej;
    });
  }

  // 3) compute final checksum by reading parts sequentially (streaming)
  // For brevity: assume we computed shaHex
  const shaHex = await computeShaForKeyParts(db, key, flushCount);

  if(shaHex !== expectedSha256Hex) {
    // rollback WAL
    await walStore.put({id: walId, key, status:'corrupt', ts:Date.now()});
    throw new Error('Checksum mismatch');
  }

  // 4) verify signature of manifest entry if provided
  if(publicKeyJwk && signature){
    const ok = await verifySignature(publicKeyJwk, hexToArrayBuffer(shaHex), signature);
    if(!ok) throw new Error('Signature invalid');
  }

  // 5) commit meta and mark WAL complete
  await meta.put({key, parts: flushCount+1, size: /*calc*/, lastAccessed: Date.now()});
  await walStore.put({id: walId, key, status:'committed', ts:Date.now()});
  await tx.complete;
}
```

**3.4 LRU eviction worker (background)**

// lru-evict.js
async function enforceQuota(maxBytes) {
  const db = await openDB();
  const tx = db.transaction([STORE_META, STORE_BLOBS], 'readwrite');
  const meta = tx.objectStore(STORE_META);
  const all = await getAll(meta); // sorted by lastAccessed asc
  let used = await estimateUsedBytes(db);
  for(const item of all){
    if(used <= maxBytes) break;
    // delete parts
    await deleteBlobParts(db, item.key, item.parts);
    used -= item.size;
    await meta.delete(item.key);
  }
  await tx.complete;
}

### 4. Service Worker: streaming fetch → IDB → validation → serve
**Principios**: no `caches.addAll` masivo; stream response body into IDB via `storeStreamWithWAL`; validate checksum/signature; then create objectURL or Response from blob parts to serve.

```js
// sw-fetch.js (inside service worker)
self.addEventListener('fetch', event => {
  const url = new URL(event.request.url);
  if(url.pathname.startsWith('/fragments/')) {
    event.respondWith(handleFragmentRequest(event.request));
  }
});

async function handleFragmentRequest(req){
  const key = deriveKeyFromUrl(req.url);
  // 1) check IDB for committed blob
  const db = await openDB();
  const meta = await getMeta(db, key);
  if(meta) {
    // serve from IDB parts
    return responseFromIDBParts(db, key, meta.parts);
  }
  // 2) fetch from network with streaming write
  const res = await fetch(req);
  if(!res.ok) return res;
  const contentType = res.headers.get('content-type') || '';
  const expectedSha = res.headers.get('x-sha256');
  const signature = res.headers.get('x-signature');
  const publicKey = await getPublicKeyForManifest();
  try {
    await storeStreamWithWAL(key, res.body, expectedSha, publicKey, signature);
    // serve from IDB now
    const db2 = await openDB();
    const meta2 = await getMeta(db2, key);
    return responseFromIDBParts(db2, key, meta2.parts);
  } catch(e) {
    // fallback: stream response to client but do not persist
    return res;
  }
}
```

### 5. P2P sync y anti-entropy (resiliente y bounded)
**Diseño**:
- **Metadata-first**: exchange manifest digests (Merkle root) not full content.
- **Chunked pull**: request missing chunks by hash; verify checksum before commit.
- **Conflict resolution**: use CRDT for mutable annotations (bookmarks, notes). For immutable fragments, use content-addressed storage (CAS) and prefer highest-signed-version.
- **Rate limiting & quota**: peers must respect `prefetchBudget` and `storageBudget` per device; reject pushes that would exceed quota.

**Sync pseudocode (peer)**

```js
// peer-sync.js
async function syncWithPeer(peer) {
  const localRoot = await computeLocalMerkleRoot();
  const remoteRoot = await peer.requestMerkleRoot();
  const diffs = compareRoots(localRoot, remoteRoot);
  for(const hash of diffs.missingOnLocal){
    if(!hasBudget()) break;
    const chunk = await peer.requestChunk(hash);
    if(verifyChunk(hash, chunk)){
      await storeChunk(chunk);
    }
  }
  // anti-entropy: periodically reconcile LRU and delete duplicates
}
```

### 6. Telemetría, pruebas y umbrales operativos
**Métricas a recolectar (local, no enviadas sin consentimiento)**:
- `usedJSHeapSize` (si disponible), long tasks count, rAF FPS, fetchQueue length, IDB write latency, WAL rollback count, signature verification failures, eviction events.

**Umbrales recomendados (iPad A10)**:
- **Heap peak**: \< 200 MB (si `performance.memory` no disponible, asumir low memory and cap writes).  
- **Long tasks**: \< 2 per minute average; si > 3/min → thermal throttle.  
- **Fetch concurrency**: default 2; reduce to 1 if deviceMemory ≤ 2 or FPS < 40.  
- **Prefetch budget**: 2 tokens, regen 1 token / 3s.  
- **IDB write chunk size**: ~64KB–256KB per chunk; flush every 8 chunks.

**Test harnesses**:
- **Install stress**: incremental install with 1 fragment at a time; measure memory and abort if approaching threshold.  
- **Swipe stress**: synthetic swipe generator that requests 20 fragments in 2s with real payloads; measure heap, long tasks, and jetsam events.  
- **Corruption fuzz**: corrupt manifest signatures and ensure client rejects and falls back to network or safe mode.  
- **P2P flood**: simulate malicious peer pushing many versions; ensure quota and rate limits prevent exhaustion.

### 7. Recuperación y forensics
- **WAL replay**: on startup, scan WAL for `writing` entries older than threshold and either resume or rollback.  
- **Snapshot + incremental backup**: periodically export manifest digests and metadata to a signed snapshot stored in Cache Storage (small) and optionally to removable media (user export).  
- **Tamper alerts**: if signature verification fails repeatedly, switch to safe mode and surface a clear UI message (no silent failures).
