## 1. DAFO GEOPOLÍTICO-SOCIOTÉCNICO: SOBERANÍA REAL

### 🔷 FORTALEZAS (Resistencia Estructural)

| Dimensión | Análisis Crítico |
|-----------|------------------|
| **Autonomía Energética-Digital** | No requiere conectividad para operar. En escenarios de colapso infraestructural (apagones parciales, ciberataques a grids, censura), el iPad A10 con carga solar/batería portátil mantiene acceso a 200K líneas de conocimiento local. |
| **Inmunidad a la Obsolescencia Programada** | Arquitectura Vanilla JS sobre HTML5 estático. Sin dependencias de npm, frameworks deprecados, o APIs cloud propietarias. Funcionará en 2035 igual que en 2025. |
| **Replicación Viral P2P** | CRDT + Bluetooth/WiFi Direct permite propagación epidémica de conocimiento sin infraestructura central. Cada dispositivo es nodo y servidor. |
| **Custodia Comunitaria** | Los datos viven en hardware de propiedad familiar (el iPad de la iaia), no en servidores corporativos sujetos a términos de servicio, fusiones, o cierres. |

### 🔶 OPORTUNIDADES (Ventanas Estratégicas)

| Vector | Potencial |
|--------|-----------|
| **Ley de Moore Inversa** | A medida que el hardware mejora, el A10 se vuelve "suficientemente bueno y barato". Mercado secundario de tablets obsoletas = infraestructura prácticamente gratuita para comunidades. |
| **Fragmentación Regulatoria** | GDPR, leyes de soberanía de datos (cloud nacional), y bloqueos geopolíticos hacen que las arquitecturas offline-first sean ventajas legales, no solo técnicas. |
| **Resiliencia Climática** | Centros de datos consumen 1% global de electricidad. Sóc de Poble consume watts de batería. En transición energética forzada, este modelo escala donde los datacenters no. |
| **Memoria Histórica Inmutable** | CRDTs con hashes criptográficos crean registros tamper-evident de conocimiento local. Resistente a revisionismo histórico digital. |

### ⚫ DEBILIDADES (Puntos de Presión)

| Vulnerabilidad | Impacto |
|----------------|---------|
| **Dependencia del Navegador** | Safari/Chrome controlan el runtime. Una actualización que deshabilite Service Workers o IndexedDB destruiría la app. Mitigación: Fork de WebKit (improbable pero técnicamente posible). |
| **Hardware Finito** | iPad A10 tiene vida útil física (batería, pantalla). Sin cadena de suministro de repuestos, el dispositivo es irremplazable a largo plazo. |
| **Curva de Conocimiento Técnico** | Mantener WAL, CRDTs, y recovery de Jetsam requiere expertise que puede no transmitirse generacionalmente. |
| **Aislamiento de Red** | Sin sincronización periódica, las comunidades divergen en silos de conocimiento incompatible. |

## 2. TEST DE CAJA NEGRA: AUDITORÍA EN FRÍO

### 🔍 Primer Vistazo del Atacante (Ingeniero de Big Tech)

> *"Veo un HTML estático, un Service Worker básico, IndexedDB... Esto es tecnología de 2015. No hay CDN, no hay Kubernetes, no hay auth OAuth. Esto no escala. Esto es irrelevante."*

**Vulnerabilidades Aparentes que Intentarían Explotar:**

| Ataque Superficial | Percepción del Atacante | Realidad Subyacente |
|-------------------|------------------------|---------------------|
| **"No tiene HTTPS"** | Interceptación trivial | Funciona offline; HTTPS es irrelevante para threat model local |
| **"Código visible"** | Reversing fácil | Open source by design; no hay secretos que proteger |
| **"Sin rate limiting"** | DoS por saturación | No hay servidor que saturar; es client-side only |
| **"IndexedDB vulnerable"** | XSS → Robo de datos | Datos son públicos por diseño; no hay PII sensible |
| **"Sin actualizaciones automáticas"** | Exploit persistence | Aislamiento air-gapped es feature, no bug |
| **"P2P sin autenticación"** | Inyección de datos maliciosos | CRDT con hashes detecta corrupción; convergencia eventual restaura integridad |

### 🛡️ Contraataque en la Sombra (Arquitectura Forjada)

Cuando el atacante profundiza, encuentra:

```
LAYER 1: Motor A10
├── Virtual Scrolling de 3 nodos → DOM inyección imposible
├── RAF throttling → No hay superficie de ataque de timing
└── Object pooling → Heap spraying inefectivo

LAYER 2: Jetsam Resistance  
├── Checkpoints criptográficos → Datos "borrados" son recuperables
├── Hash chains SHA-256 → Cualquier modificación es detectable
└── Cache API fallback → Redundancia sin servidor

LAYER 3: P2P CRDT
├── Vector clocks → Ataques de replay detectados
├── LWW conflict resolution → Consenso sin coordinación
└── Tombstones persistentes → Borrado "ofensivo" no destruye

LAYER 4: Thermal Predictor
├── Modelo de comportamiento → Detecta anomalías de uso (side-channel)
└── Throttling proactivo → Mitiga ataques de consumo de recursos
```

**Conclusión del Red Team honesto:** *"No hay superficie de ataque convencional. Para destruir este sistema necesitarías destruir el hardware físico de cada instancia distribuida, o comprometer el navegador a nivel de motor (WebKit/Chromium), lo cual escala a miles de millones de dispositivos, no solo este."*
