## 📊 PART 1 — Diagnosi Umami: Nota 8/10 + Bug Trobat

L'enfocament de l'arquitectura és **sòlid (8/10)**: atacar l'API directament és millor que un iframe. El 2 que falta és per manca de gestió d'errors granular i per l'exposició de l'API key en un document compartit (no fer-ho mai en producció — ha d'anar a `.env`).

**El bug principal:** L'API d'Umami v1 retorna objectes anidats amb `.value` i `.change`, no valors directes:

```json
{
  "visitors":  { "value": 450,  "change": 20 },
  "pageviews": { "value": 1000, "change": 50 },
  "visits":    { "value": 600,  "change": 30 },
  "bounces":   { "value": 150,  "change": -10 },
  "totaltime": { "value": 54000,"change": 2000 }
}
```

El codi actual fa `stats?.visitors || 0` → retorna l'objecte sencer (que és *truthy*), i React o el mostra com `[object Object]` o llança "Objects are not valid as a React child". La correcció és `stats?.visitors?.value ?? 0`.
